# Bounded last-bar engine

`lastbar` is the built-in and Web-configured default. It runs Exhaustive at its unchanged per-stock-length budget, then spends up to 10,000 additional charged steps on relaxed last-bar rearrangements for that stock length. This is a heuristic, not a proof of optimality or a wall-clock limit. It leaves leftovers unchanged, validates the baseline and every accepted result by exact part reference and fit, and retains Exhaustive's First Fit fallback metadata. No migration is required: saved results record the selected engine id/name through existing JSON fields. Existing saved plans are not recomputed automatically; re-optimizing a saved plan uses its recorded engine unless the operator changes the picker.

On a deployment built from this revision, a new job defaults to “Exhaustive + Last-Bar” in Results. To compare or revert per job, select “Exhaustive” before Optimize or Re-Optimize. For a non-persisting preview, use `POST /api/jobs/{id}/pack` with JSON `{"engine":"exhaustive"}` or `{"engine":"lastbar"}`; `GET /api/packing/engines` lists both. Standalone optimization and MCP selectors also use the catalog. The Web default can be reverted by setting `Packing:DefaultEngine` to `exhaustive`. Publishing a container does not redeploy a running application.

A prior test-only experiment on 120 synthetic development jobs found three fewer bars across three jobs after Exhaustive with this additional 10k budget; see [last-bar-elimination-evaluation.md](last-bar-elimination-evaluation.md). A catalog-to-`MultiBinPacker` regression for repeated seed 36 verifies 98 → 97 bars with exact reference conservation. The zero-budget and invalid-baseline suite verifies no unsafe partial promotion. The pre-existing same-named near-equal part removal defect was fixed by reference-based `Bin.RemoveItem`, covered through full First Fit and prototype paths.

Real-job check: from the saved `/mnt/rogers/Drawings` inventory's largest listed cut-list text file by byte size (only one level beneath top-level job folders; not an archive-wide maximum), reconstructed 56 parts, 240-inch stock, 1/8-inch kerf, and 12 historical bars. Every historical bar implies 240 inches at that kerf; the source's `{totalLength}` placeholder alone does not supply stock. In 31 alternating, warmed-up, Release pairs through the real catalog and `MultiBinPacker`, both engines used 12 bars with zero unplaced parts and exact reference conservation/fit. Exhaustive median/p95: 1.879/2.074 ms; lastbar: 1.913/2.180 ms. The median difference was 0.034 ms (1.81%) on the measured host. A second 31-pair run after selecting lastbar as the default measured 1.971 ms for Exhaustive and 1.954 ms for lastbar; the overlap illustrates shared-host timing noise. This particular job gains no bars.
